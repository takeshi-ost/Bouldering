# iOS Firebase 接続と通常同期（0.4.57）

## モード

既存の bouldering-7482d、固定 Firebase Web SDK 12.11.0、iOS 専用アダプターを使う。Firebase 側の設定は変更しない。

- `auto-sync`（通常 Debug／Release の既定）: 保存済み認証を復元する。新規利用者だけ匿名認証を作成し、本人のプロフィールと新規通常ステージ記録を同期する。
- `offline`: SDK 初期化・外部通信を行わない。CI のシミュレーター起動はこちらを明示指定する。
- `read-only`: 認証と読み取りだけ。プロフィール／記録を書き込まない。

assets と Xcode の通信モード不一致はビルドを停止する。通信モードとゲームの DEBUG 切替は独立し、Release のゲーム DEBUG は OFF 固定。CSP の通信許可先は既存の Firebase 3 ホストのみ。

## UID と記録

認証復元を優先し、保存された UID・チェックポイント・キュー所有者が食い違う場合や、既存 UID の認証を復元できない場合は新しいアカウントへ置き換えない。永続化できなければ登録しない。新規の初回接続前のクリアとプロフィール編集も、既存の専用キューに所有者未確定として保存し、認証した UID に一度だけ結び付ける。

通常記録は v4、その回の実際のクリアを送る。パス表示を使った挑戦は対象外。Daily は v3 のローカル記録で、通常ランキングへ送らない。旧 Web 保留記録と過去の local best は取り込まない。サーバーに良い記録がある場合は維持する。

新規プロフィールは現在の名前と配色を使う。既存のサーバー名は本人の明示編集がなければ維持する。現在世代の到達値だけ最大値を同期し、旧世代の到達値は合成しない。サーバー値によるローカル進行の上書きはしない。

## オフラインと再接続

通信不能でもローカルプレイと保存を継続する。online・focus・ネイティブ復帰で起動接続全体を再試行し、重複呼出しをまとめる。明確にオフラインなら匿名作成リクエストは発行せず、後で接続できる。

実際に匿名作成を送った後、応答が不明で認証も保存されていない場合は、既存の試行マーカーにより二重作成を停止する。この状態は自動で解決する保証がなく、個別確認が必要。マーカーや UID を消して再登録する処理は追加していない。

## ビルドと検証範囲

通常は `npm run sync:ios` で auto-sync。オフライン検証は `ASCENT_FIREBASE_MODE=offline npm run sync:ios` と Xcode の `ASCENT_FIREBASE_MODE=offline` を対応させる。

0.4.57 の自動試験はモックとローカル生成物のみ。実サービス登録・実データ書込み・実機更新は行わない。過去版での実機通信成功は、新版の実接続成功を意味しない。長期オフライン、トークン更新、実機の初回登録は別途確認が必要。

引き継ぎ・削除の既存制限は維持。診断は Debug 専用の明示フラグで件数・真偽・安全なエラーコードだけを扱い、UID・トークン・文書本文を出力しない。
