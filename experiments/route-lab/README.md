# ASCENT Route Lab — 従来式ベースの骨格比較

本人限定URL: https://ascent-route-lab.activeboar15.chatgpt.site

- 基準: GitHub `372855820cff937c1414cd741301559a60453279` / 0.4.6。試作版 **0.2.1**。
- **0.2.0の規則的な2列配置は削除しました。** 元の配置生成そのものを呼びます。旧 `prototype.js` の復活ではありません。
- 通常版モジュールはバイト一致を検証してコピーし、差し替えは試作の `integration/skeleton.js` に限定。Macの未push／未コミット変更は含みません。
- 旧方式の入口も維持。比較へ戻ると条件保持、最初からは同条件、hashでも条件を再現。進行はメモリだけで、入口／外側リセット／再読み込みで消えます。

## 実際に再利用する従来処理

1. `createStageGenerator().generate(1)` で元STAGE 1の密度基準を較正。
2. 元の `stageLayout` と `generate` でガイド、ホールド、開始姿勢を作成。元の `fillWall` が乱数で周囲のホールドを追加し、`convergeDensity` が密度を調整。
3. 元の `assignWideHolds` → `solveRoute` → `pruneUnusedHolds` → 標準 `optimizeRoute`（900遷移・2pass）を使用。
4. 元の `finalizeCourseGeneration('basic')`、接触再生、スタミナ検証を通す。今回は回復・尖ホールドなし。

独自の列を作ってソルバーだけ流用する方式ではありません。seedは実際の散布位置・幅広ホールドにも効きます。

## 骨格ごとの差分

- **ストレート**: ショートは元STAGE 1の専用ガイド・配置をそのまま使用。**seed 1の最終配置・ルート・密度統計・レシピは従来STAGE 1と一致**。ミドル／ロングは元の通常ステージの間隔計算・配置を使い、`makeStageCourse` の骨格だけ垂直線へ変更。
- **蛇行**: 元の `makeStageCourse` の上昇・横断・折り返しをそのまま使用。変えるのは選択した長さのルールだけ。
- **分岐**: 元の散在配置から別の手掛かりを使う経路を残す方式。新しい格子やレーンは追加しません。元の前後の経路を維持し、最大500pxの局所区間だけを別経路へ接続。本線ポリラインから45px以上離れ、本線にない接触を2個以上使い、既存スタミナ内で届く場合だけ採用。
- 分岐も元の剪定を使いますが、どちらかの経路の接触・支持選択が変わる削除を拒否して両方を保持。標準の短縮後にも局所合流・予算を再検証し、両立しない場合は短縮前の検証済み経路を維持。
- ショートの分岐は開始付近から分かれ、共通ゴールで合流する場合もあります。全件が途中で同一姿勢に戻るという意味ではありません。ゴールは本物1個だけ。
- 長さは壁高700／1400／2100px。同じ長さ・seedでも種類間の経路長・手数・難易度は異なります。
- ハート回復・尖ホールド・複数区間合成は未実装。確定移動で1消費、検証経路手数+3の開始スタミナなどは元の規則。
- ストレート／分岐はソルバーの水平移動必須判定を外すため試作内level=1。蛇行は通常のlevel=2判定で横断も要求。通常版のステージ設定は変更しません。
- 分岐は最大6回の限定探索＋各96候補の局所接続再生。見つからないseedは明示エラーとし、別タイプへ黙って代替しません。
- 短縮前→後コストは見つかった経路のもの。最短・完全探索の保証ではありません。線は任意表示（青：本線、橙：別経路）。

## 起動・テスト

Node.js 22以上。依存インストール不要。

```sh
git clone --branch experiment/route-lab --single-branch https://github.com/takeshi-ost/Bouldering.git
cd Bouldering/experiments/route-lab
npm run build
npm test
npm run dev
```

ローカルは `http://127.0.0.1:4173`。`BASELINE_ROOT` を指定する場合は同じ基準コミットの素材が必要です。`baseline-manifest.json` に固定した73ファイルのGit blob SHAが異なるとビルドを拒否します。

`public/game/` は再生成物でGit管理外。リポジトリの既存ルート素材から生成し、配信するのは `public/` だけです。リポジトリルートをWeb公開しないでください。

## 分離の実装

- 本番Firebase SDK・online・online-scores・引き継ぎ・アカウント削除・旧prototypeモジュールは配信物から除外。
- 代替APIはUIDなし、アダプターなし、送信キューなし、リモートプレイヤーなし。結果はこの試遊内の自分の記録のみです。
- CSP `connect-src 'none'` で通信を拒否。画像・スクリプト・CSSは同じSiteだけ。外部CDN、広告SDK、購入は使いません。
- 効果音8本＋BGM2本は元の音源をメモリに同梱。fetch互換関数はその10本だけをメモリから返し、他URLは拒否します。ネイティブfetchへ転送しません。
- localStorage/sessionStorage互換オブジェクトはメモリのみ。ブラウザに保存済みの値を一度も読みません。本番の保存・UIDを取得しません。
- iframeは `allow-scripts allow-same-origin`。これは同一Site内の資源を動かすためで、iframe自体を強いセキュリティ境界とは扱いません。分離の根拠は本番とは異なるSite origin、禁止CSP、配信対象除外、メモリ保存です。
- 外側の入口・リセット・履歴移動でiframeを破棄／作成し直します。キャンセルは現状維持。ゲームの広告は元から存在するローカル10秒ダミーで、その旨を表示します。
- 本人限定ログインはホスティング側のアクセス制御です。ゲームのFirebase認証とは別です。

## 検証

- 元STAGE 1の生配置・最終配置と完全一致する比較テスト。蛇行も元の長さ選択と一致するseedで生配置を比較。
- seedで散在ホールドの相対座標が変わり、平行移動だけではないことを確認。密度調整・剪定の実行も統計で検査。
- 3種類×3長さ×seed 0/42/2026 の27条件で再現性と実touchstart/move/endハンドラ登頂。分岐の別経路もseed42の3長さで登頂。
- 比較UIの同条件リセット・取消・履歴移動・無効入力、現iframeかつ同一originからの通知のみ受理を検査。
- 既存方式の実touch入力、コピーした元ソースの一致、通信隔離・メモリ保存・配信範囲も継続検査。
- 実機iPhoneの修正版操作・音・レイアウト、モバイルviewportの実測は未検証。Nodeのtouch検査と実機は区別。
- 元基準版の7スクリプト（通常20ステージを含む）は前回更新時に成功し、元ソースは今回も不変。通常版の全件スイート・Mac/iOSネイティブ・全seed・完全最短探索は未実行。
