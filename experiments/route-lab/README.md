# ASCENT Route Lab — 単独骨格の比較試遊

本人限定URL: https://ascent-route-lab.activeboar15.chatgpt.site

- GitHub基準: `372855820cff937c1414cd741301559a60453279` / 0.4.6。試作バージョン: **0.2.0**。
- 通常版の操作・吸着・スタミナ・描画・探索モジュールはバイト一致を検証してコピーします。新骨格は `integration/skeleton.js` だけに実装。
- Macの未push／未コミット変更は含みません。旧 `prototype.js` は配信・再利用しません。
- 骨格・長さ・seedを選んで直接プレイ。比較へ戻ると条件が残り、「最初から」は同条件。URLのhashも条件を再現します（保存データではありません）。
- 旧方式は別ボタンからタイトルTAP→STAGE 1→スタート。進行・記録・設定はメモリ内だけで、入口／最初から／再読み込みで消えます。

## 今回の骨格ルール

- **ストレート**: 縦の本線。seedは小さな横位置差に使います。左右の持ち替えが起きることはあります。
- **蛇行**: 周期350〜370px、振幅72〜78pxの左右に曲がる本線。鏡映・振幅・周期・位置はseedで固定。
- **分岐**: 暫定仕様として、直線の本線の中間1か所に横へ膨らんで戻る寄り道を置きます。高さ最大400pxの局所区間だけに追加し、遠く離れた本線区間同士はつなぎません。ゴールは共通の本物1つ。行き止まりや偽ゴールはありません。
- ショート／ミドル／ロングは同じ壁高700／1400／2100px。同じseed・長さでも、種類間で道の長さ・手数・難しさが同じという意味ではありません。
- 今回はハート回復・尖ホールド・複数区間の組み合わせなし。元の「1回の確定移動でスタミナ1消費」「探索ルート手数+3の開始スタミナ」を使います。
- 既存ソルバーはSTAGE 1以外に水平移動を要求するため、試作内だけlevel=1としてその制約を外します。ただし専用の新配置を生成し、STAGE 1のチュートリアル配置・駅点は一切使いません。
- 元の限定探索で1本のクリアルートを確認し、元の接触再生・スタミナ検証を通してから開始します。分岐では同じ最終配置で、実際に横へ65px以上寄る別経路も検証し、本線のスタミナ内で届くものだけ開始します。
- 60手・beam12の元ソルバー、500遷移・1passの経路短縮が上限。表示する短縮前→後のコストは見つかった経路のもの。最短・完全探索・難易度保証ではありません。
- 検証失敗時は同じ画面にエラー。別タイプや旧方式へ黙って代替しません。戻って別seedを選べます。
- 線の表示は任意。青は本線、橙は分岐の寄り道の検証経路です。両経路を残すため、分岐のホールドを本線だけに合わせて削除しません。

## 起動・テスト

Node.js 22以上。依存インストール不要。

```sh
git clone --branch experiment/route-lab --single-branch https://github.com/takeshi-ost/Bouldering.git
cd Bouldering/experiments/route-lab
npm run build
npm test
npm run dev
```

ローカルは `http://127.0.0.1:4173`。`BASELINE_ROOT` を指定する場合は同じ基準コミットの素材が必要です。`baseline-manifest.json` に固定した73ファイルのGit blob SHAが異なるとビルドを拒否します。

`public/game/` は再生成物でGit管理外。リポジトリの既存ルート素材から生成し、配信するのは `public/` だけです。リポジトリルートをWeb公開しないでください。

## 分離の実装

- 本番Firebase SDK・online・online-scores・引き継ぎ・アカウント削除・旧prototypeモジュールは配信物から除外。
- 代替APIはUIDなし、アダプターなし、送信キューなし、リモートプレイヤーなし。結果はこの試遊内の自分の記録のみです。
- CSP `connect-src 'none'` で通信を拒否。画像・スクリプト・CSSは同じSiteだけ。外部CDN、広告SDK、購入は使いません。
- 効果音8本＋BGM2本は元の音源をメモリに同梱。fetch互換関数はその10本だけをメモリから返し、他URLは拒否します。ネイティブfetchへ転送しません。
- localStorage/sessionStorage互換オブジェクトはメモリのみ。ブラウザに保存済みの値を一度も読みません。本番の保存・UIDを取得しません。
- iframeは `allow-scripts allow-same-origin`。これは同一Site内の資源を動かすためで、iframe自体を強いセキュリティ境界とは扱いません。分離の根拠は本番とは異なるSite origin、禁止CSP、配信対象除外、メモリ保存です。
- 外側の入口・リセット・履歴移動でiframeを破棄／作成し直します。キャンセルは現状維持。ゲームの広告は元から存在するローカル10秒ダミーで、その旨を表示します。
- 本人限定ログインはホスティング側のアクセス制御です。ゲームのFirebase認証とは別です。

- 元コードの routes/input/rules/retry-stage-start/title-startup/course-generation/course-length は今回も再実行。routesは通常STAGE 1〜20を実入力処理でクリア。
- 骨格は3種類×3長さ×seed 0/42/2026 の27条件を2回生成して一致確認し、touchstart/move/end実ハンドラでクリア。分岐の寄り道はseed42の3長さで同様に検査。
- 比較UI: 同条件リセット・取消・戻る/進む・再読み込み・不正設定・別seed・同一originかつ現iframeからの状態通知だけ受理。
- ブラウザでストレート/ショート/seed42をドラッグで登頂し、結果から同条件再プレイ、比較画面復帰を確認。分岐の2つの経路表示も確認。
- 元の基準版は利用者がiPhoneで操作確認済み。**新骨格の実iPhone操作・音・レイアウト、モバイルviewportのブラウザ実測は未検証**。Node上のtouchハンドラ検査は実機検証とは区別します。
