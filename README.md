# ASCENT

胴体をスワイプし、四肢のうち2点を固定して残り2肢を動かすクライミングパズルです。

## 起動

[index.html](index.html) をブラウザで開き、タイトル画面の準備完了後に「TAP」をタップするとスゴロク状のステージマップが開きます。STAGEのコマをタッチすると、難易度・コース長を表示する開始前モーダルが開きます。「スタート」でプレイを開始します。マップ・ステージの設定モーダルの「くわしい説明」から操作やホールドのルールを確認できます。ビルド・インストールは不要です。ゴール側から一定速度で最下段へスクロールし、中央にSTAGE番号を表示し、最下段への到着と最低1秒の表示を満たすと操作可能になります。1画面のステージでも1秒表示します。

- クリアすると次のSTAGEを解放し、結果画面の「次のステージへ」からマップへ戻るとコマが1つ進みます。クリア済みSTAGEも選び直せます。MAPで現在の挑戦を終了してマップへ戻れます。進行はコース別に端末へ保存します（保存できない環境では、そのセッション中のみ維持します）。
- 全ステージ、最下段の2個のホールドに両足、上方の横長ホールド1個に両手を置いて開始します。足幅は140px以内に収め、開始時だけ4接触を保って胴体をできるだけ低く構えます。開始用3ホールドで囲む三角形内は通常ホールドの配置を避けます。
- コース長は難易度と独立にショート・ミドル・ロングを2:5:3の重みで選びます。ショートは1画面、ミドルは2画面、ロングは3画面の高さを使い、各上端付近にゴールを置きます。STAGE1だけはショート固定です。
- フィールド中央からスワイプして移動します。左右16px（400px幅のゲーム座標）はスクロール専用セーフゾーンです。通常は表示せず、端からスクロールしている間だけ操作した側をグレーの単色で表示します。コースの横幅と開始・通常・横長・消費・ゴールのホールド配置を内側へ縮めています。この領域から始めたスワイプ／マウスドラッグは、プレイヤー操作にせずステージを上下スクロールします。中央へ移動しても指を離すまでスクロールを維持します。
- 支持ペアは6組を内部評価し、開始方向への移動先が多い組、同条件なら移動距離が長い組を選びます。
- スワイプ中は2点を固定し、残り2肢の吸着先はリアルタイムに変化します。
- 足先の上限はボディ中点です。股関節より高い足は膝の内角150度以上（ほぼ直線）で届く場合だけ許可します。固定足を支点に動く途中も判定し、両コースの生成・再生で検証します。
- 四肢の骨は固定長です。関節と胴体を「足先より低い膝の数 → 全違反数 → 共通コスト」の順で評価します。膝の高さは股関節基準から足先基準へ置き換えました。近い手では肘を低く保つことより外向きを優先する場合があります。手足はボディの奥に描きます。 四肢固定後は同じ評価式で描画上の胴体位置も調整し、4つの接触を保てる移動経路で姿勢が改善する場合に移動します。
- 全四肢が吸着していれば移動を確定でき、1手消費します。同じ4接触位置への復帰やキャンセルは消費しません。
- プレイヤーのボディは押している間だけ3px沈んで色が変わり、短くタップすると直前の確定移動を1回取り消し、姿勢・手数・スタミナを戻せます。新しい移動後は再び利用できます。結果モーダル表示中は背景操作を受け付けません。
- 横幅2倍のホールドは両手、または両足で共有できます（手足混在は不可）。両コースとも開始用1個＋途中0〜2個を配置します。
- 両手でゴールを掴むとクリア。開始スタミナは全ステージで「想定手数＋3」です。想定手数には想定ルート上の紫ホールドの追加消費を含みます。ハート数による初期値の減算はありません。クリア時の残量は持ち越しません。
- 難易度1〜3の想定5手以上のルートに❤️を0〜2個配置します。1個なら前半、2個なら1個目を1/3・2個目を2/3までに置き、回復がゴール直前に偏るのを防ぎます。ボディが触れるだけでスタミナが2回復し、取得位置に「+2」が1秒で30px上昇しながら消えます。4肢が吸着していない姿勢でも取得できます。キャンセル・Undoでも取得と回復分は維持し、同じ❤️の重複取得はできません。RETRY／RESTARTでは開始状態に戻します。
- 難易度2は青く小さいギザギザのホールドを0〜5個追加します。新たに保持して移動を確定すると、通常の1手に加えて1個につきスタミナを1消費します。同じ四肢での保持継続は追加消費せず、持ち替え・離した後の再保持では毎回追加消費します。キャンセルは無料、Undoは消費分も戻します。ルート付近や近道になりそうな位置へ置き、難易度2では使わないクリアルートを維持します。難易度3は通常ホールドとハートの配置を固定した後、全ホールド数の10〜30％を消費ホールドへ変換します。開始時の保持先・ゴール・大きなホールドは変換せず、ルート内外を区別せず通常ホールドから抽選します。変換後に実消費コストで探索・短縮し、ハート取得の時系列も含めて完走を検証します。想定ムーブは移動回数だけを数え、スタミナはその値＋3です。
- スタミナ切れでは四肢を離して下へ加速し、画面外へ落下します。カメラは固定し、落下中はスクロールできません。失敗時は中央の結果モーダルからリトライできます。ゴールと同時に残量0になる場合はクリアを優先します。
- ステージを2本指で上下にスワイプするとスクロールできます。PCではホイール、またはステージにフォーカスして方向キー等でスクロールできます。
- 操作可能になった瞬間からクリアまでを計時します。中央の結果モーダルに「手数 分:秒:1/100秒」を表示し、通常プレイのクリア記録をコース別・ステージ別に端末へ保存します。マップではステージの横に表示し、再クリア時は最新の記録へ更新します。過去の進捗は維持し、未計測ステージは再クリア時に記録します。デバッグプレイは保存しません。
- スタミナは左上の❤️で表示します。右上の手数／想定手数はマップ設定の「デバッグモード」がONのときだけ表示します。
- マップ設定の「デバッグモード」で想定ルートを表示します。クリア後はデバッグ設定にかかわらず、実際の確定位置を結ぶルートを自動表示します。

## キャラエディット

マップ設定の「キャラクターエディット」から、中央のプレビューで配色を編集できます。スライダーでボディを上下に1〜8等分し、各段または頭をタップすると右側に縦長の16色パレットがモーダルで開きます。色を1回タップすると、その部分に適用して閉じます。外側のタップ・Escapeでは色を変えずに閉じます。自由な色の入力はありません。プレビューの輪郭・肩腰の4点・手足の線幅はステージ表示と揃えています。「おまかせ」は初期設定と同じ方法で段数・各段の色・頭の色をランダムに作り直します。名前は維持し、配色は「決定」まで下書きとして扱い、「戻る」で破棄します。編集中に分割数を減らしても、数を戻すと選んだ色を復元します。初回起動で保存がない場合も1〜8段と各色をランダムに設定し、すぐに保存します。隣り合う段は異なる色にし、保存済みの配色は再読み込み後も維持します。保存できない場合もセッション内では適用します。

## 本仕様と検証用モード

- **本仕様**：従来の生成・密度調整・ルート検証・削減処理をそのまま使用します。
- **ロジハラ（検証用・デバッグモード時のみ）**：同じSTAGEの初期ガイドパス・開始位置・ゴール・壁高を共有します。ガイド沿いに不均等な間隔と位置の揺らぎを持つ手足の候補だけを置き、実操作と同じルールで解法を求めます。壁全体への追加や密度調整は使いません。
- 試作では求めた胴体ルートを固定し、通常ホールドを1個ずつ仮削除して全手を再生します。支点や接触先が変わっても通過できれば削除し、削除できなくなるまで繰り返します。残った通常ホールドはどれも、このルートの再生に必要です。全組み合わせでの最少個数を保証するものではありません。
- 初期ガイドを共有しますが、探索後の手順・ホールド・手数はコースごとに異なります。触れないホールドも支持ペア選択に必要な場合は残します。
- マップ設定の「タイトル画面へ」でタイトルへ戻れます。検証用モードへの切り替えはデバッグモードON時のマップ設定から行えます。コースごとにクリア状況を維持し、RETRY／RESTARTは選択したSTAGEをやり直します。

青ホールドの追加消費時はボディだけを280ms横に震わせ、各ホールド位置に青い「-1」を表示する。文字は❤️の「+2」と同じく1秒で30px上がりながら消える。確定前・保持継続では発火しない。Undo・再開始・マップ復帰で震えを解除する。論理姿勢・保持先には影響しない。

マップ設定の「デバッグモード」をオンにすると、マップの番号入力で任意のステージをプレイでき、ゲーム中に想定ルートと手数／想定手数を表示する。切り替えUIはマップ設定に置き、ステージ設定で想定ルート・ホールドNo・コース情報を個別に切り替える。通常の解放制限は維持し、デバッグで入ったステージはリトライ後もクリア進捗を保存しない。マップへ戻ると通常の次ステージ位置へ戻る。デバッグモードは永続保存しない。

画面全体を使う一層構成とし、共通ヘッダー・フッター・外枠は表示しません。ゲーム上部は左に❤️、中央にLEVEL、右に歯車を配置します。歯車から設定モーダルを開き、RESTART／MAPにもどるを選べます。設定中は移動・Undo・スクロールを停止しますが、計測時間は進みます。

クリアモーダルの星は、想定手数以下で⭐️⭐️⭐️、想定手数＋1〜＋2手で⭐️⭐️、それを超えると⭐️です。クリア・失敗とも小さな補足メッセージは表示しません。

マップのクリア済みSTAGEアイコン下部に獲得した星を小さく表示します。星はコース・STAGE別の最高評価を保存し、再プレイで減りません。星の保存前のクリア記録には、再クリア時に星が追加されます。

本仕様のプレイ入口は準備完了後のタイトル画面タップに統一します。ロジハラは検証用としてデバッグモードON時のみ入口と説明を表示します。通常プレイではモード名を表示しません。既存の進行・配色・記録・星は維持します。

## デイリーチャレンジ

マップ右上の「デイリーチャレンジ」から月単位のカレンダーを開きます。画面上部にはマップと同じ空と日付入り飛行船を配置し、カレンダーと開始欄をその下へ配置します。見出しは空画像の上の左上に表示し、右上にマップと同じ設定ボタンを置きます。飛行船をタップすると元のマップへ戻ります。「マップへ」テキストボタンとカレンダーの端末時刻表示は置きません。端末時刻の今日までの未クリア日付をプレイでき、カレンダーは全体を下地プレートで囲み、日付行の高さを従来の約2/3にします。未クリア日は枠・ボタンアイコンのない数字、クリア済み日は仮の✓アイコンで並べ、選択日だけ青いプレートを表示します。未来日は選択できず、タップしても直前の選択を維持します。前の月にも移動できます。カレンダー上の右スワイプで前月、左スワイプで翌月（現在月まで）へ、日付面が横にスクロールして移動します。矢印ボタンも同じ表示です。上下スクロールは無効にし、6週の月とクリア記録を含め、画面高に合わせて日付行を調整します。月移動後の誤選択を防ぎます。端末の午前0時をまたぐとカレンダーを更新します。日付の選択ではゲームを開始せず、下の開始欄へ対象日・難易度・コース長を反映します。「スタート」で広告判定・コース生成・開始へ進みます。開始欄はページ内に常設し、ライフ・アイテム・閉じるボタンは置きません。初期選択は今日です。過去月へ移動すると必ずその月の末日を選択し、現在月へ戻ると今日を選択します。末日がクリア済みなら保存済みの記録を表示します。

選択した日付をUTCの暦日としてシード化し、難易度0〜3を設定割合で選び（初期値は各25%）、配置・横長ホールド・ハート・青ホールドを日付のシードで生成します。同じ日付はリトライや再起動でも同じコースです。クリア・失敗の結果モーダルからカレンダーへ戻り、設定からも戻れます。デイリーの初回クリア記録と獲得星は通常進行と分けて保存し、クリア済みの日を選択すると、開始欄のスタートを隠し、保存済みの星・手数・タイムを表示します。一度クリアした日付は再挑戦できません。

## 難易度と選択割合

追加ルールはステージ番号から独立した難易度で決めます。コースの長さ・形の進行変化と、スタミナ余裕は全ステージで＋3です。

| 難易度 | 回復ハート（想定5手以上） | 青ホールド | 通常進行の初期設定 |
|---|---|---|---|
| 0 | なし | なし | STAGE 1〜4で100% |
| 1 | 0〜2個 | なし | STAGE 5〜19で100% |
| 2 | 0〜2個 | 任意に使う0〜5個 | STAGE 20〜39で100% |
| 3 | 0〜2個 | 配置後の全ホールドの10〜30％を変換し、その後に探索・検証 | STAGE 40以降で100% |

`js/config.js` の `DIFFICULTY_CONFIG.stageBands` に開始STAGEと4つの重みを指定します。並びは難易度0・1・2・3です。例えば `{fromStage:20,weights:[0,20,60,20]}` なら、その区間で難易度1が20%、2が60%、3が20%になります。区間は次の `fromStage` の直前までです。重みは合計100以外でも比率として正規化します。

デイリーの割合は同じ設定内の `dailyWeights` で独立に指定します。同じ日付・同じ設定なら難易度も配置もリトライで変わりません。デイリーの形の基準は難易度0から順にSTAGE 4・5・20・40相当で、追加ルールは選ばれた難易度そのものに従います。デバッグ表示には選ばれた難易度も表示します。

難易度の画面上の表記は0が「EASY」、1・2が「NORMAL」、3が「HARD」。通常・デイリーともクリアモーダルに表示し、デバッグ時のゲーム中表示も同じ呼称を使う。失敗モーダルには表示しない。

ステージマップは全面表示で、見出しとデイリーチャレンジを上部に重ね、設定ボタンを右上に置き、タイトルへの移動・キャラクターエディット・説明を設定内にまとめます。ページは1〜20、21〜40のように20STAGEずつ重複なく表示します。マップ内の最上段より上・最下段より下にある△で次・前の20STAGEへ移動します。上向き△は固定された空の下へ配置し、上下ともプレートなしの画面幅約1/4の横長三角です。△はマップと一緒にスクロールします。クリア済みのマスには星のみ表示し、手数・タイムはクリアモーダルで確認できます（記録の保存は維持）。

キャラエディットでは最大10文字のプレイヤー名も設定できます。初期値はランダムな英数字8文字で、一度保存した名前は維持します。日本語・絵文字も表示上の1文字として数え、空欄は保存できません。名前と配色は「決定」で保存し、「戻る」で下書きを破棄します。

通常プレイでは再プレイも含め5回クリアするごとに、「次のステージへ」からダミー広告へ進みます。単色画面に「広告」と10→0のカウンターを表示し、10秒後の「完了」タップでマップの次ステージへの移動演出へ戻ります。回数は端末に保存し、広告を完了するとリセットします。デイリー・ロジハラ・デバッグ・失敗は通常プレイの5回カウント対象外です。共通処理 `startDummyAd({onComplete,onReturn})` は完了処理を実行した後、呼び出し元のシーケンスへ復帰します。広告は現時点ではダミーで、実広告SDKは未導入です。

デイリー広告は対象の日付ごとに判定します。初回のクリア後は「カレンダーへ」、失敗後は「リトライ」タップ後に表示し、2・4・6回目以降は開始前に表示します。未クリアで「カレンダーへ」戻る場合はその場で表示せず、次の日付を選択して「スタート」を押した後に広告を表示してから開始します。別の日付を選んだ場合も適用します。初回結果から直接リトライする場合は広告を1回だけ挟み、2回目の開始前広告も兼ねます。挑戦回数は日付別に保存し、ゲーム中のRESTARTでは増やしません。

通常ステージにはライフを適用します（デイリー・ロジハラ・番号指定デバッグは対象外）。初期3、最大5、実時間30分ごとに1ずつ3まで自然回復します。失敗・途中退出・プレイ中のRESTARTで1消費し、失敗後のリトライでは重ねて消費しません。0で開始しようとすると広告の確認を表示し、「広告を見る」→ダミー広告完了で1回復して選んだステージを開始します。画面のLIFEはステージ内スタミナの❤️とは別の値です。残数・回復時刻を保存し、閉じていた時間も回復します。

ゴールが高いステージには、ゴール中心から上に180px（ゲーム座標）の表示余白を確保できるカメラ範囲を追加します。STAGE 1など従来1画面内のステージでも上へスクロールでき、開始プレビュー・自動追従・2本指スクロールに共通の上端を適用します。コースの座標・ホールド間隔・想定手数は変更しません。

キャラエディットのプレビューは、ボディの塗り分け数に合わせて8種類のポーズへ切り替わります。1：自然立ち、2：片足重心、3：腰に手、4：前で手を組む、5：頭に手を添える、6：脚組み、7：腕組み、8：脚を広げて胸に手。ポーズは編集画面専用で、プレイ中の姿勢制御には影響しません。

マップは淡色の記号的なイラストで、山・針葉樹・テント・マット付きの屋外ウォール・三角旗・草を道の周辺に配置します。道は輪郭のある小道として描き、ステージの丸いマス・星・キャラクターアイコンは維持します。風景はマップと一緒にスクロールし、装飾へのタップはステージ操作を妨げません。

### タイトルの起動準備

タイトルはステージの壁背景にASCENT・リリースバージョン・UIDを表示し、左下にデータ引き継ぎボタンを置きます。UUIDを一時表示せず、取得済みUIDは起動直後から、初回認証の完了までは「UID 接続中…」を表示します。背景は最下段から最上部まで約5分で移動し、到達後は停止します。マップ20ステージ分の準備と画像・フォント読込、2描画フレームを待ってTAPを表示し、準備前のタップは無効です。

### マップの表示

ステージアイコンは押している間に絵が拡大し、短いタップ後も拡縮の反応が残ります。ステージからマップへ戻るときは、画像と配置が整うまで前画面を表示し、準備後に切り替えます。次のステージへ進む演出もマップ表示後から始まります。

### 開始前の確認

開始前モーダルにはライフ／回復時間・STAGE番号・難易度・長さとスタートを表示します。アイテム選択は置きません。×や外側タップで閉じてもライフは減りません。「スタート」後に既存のライフ確認と開始演出へ進みます。

コース長の表示は「ショート／ミドル／ロング」に統一します。開始前モーダルは左2/3に「STAGE 0000」が収まるサイズで「STAGE 1」のようにゼロ埋めせず1行で左寄せ表示し、右1/3に難易度・コース長を縦に表示します。規定スタミナとハート追加数は下段で「❤️10＋［❤️00］」の形に同サイズで並べ、規定スタミナはステージHUDと同じハート内の数字で表示します。追加数ボタンのタップごとに1個増やし、右肩の✖︎バッジで0個へ戻します。所持数には選択分を除いた残数を表示します。デイリーの開始欄も同じ配置で、左側に年と大きな月日を表示します。その他のステージ番号はゼロ埋めせず4桁分の幅を確保し、ステージアイコン内と開始演出は中央寄せ、それ以外は左寄せです。開始演出は実際に表示する文字列の幅で中央に揃えます。広告後のマップ復帰では、画像と配置の準備が完了するまで広告画面を維持し、ゴール画面を再表示せずに移行します。

## 効果音

Web Audioで短いSEを合成します。ボタン・選択、月移動、配色編集の確定、ステージの操作解禁、移動確定、無効な移動、回復ハート、消費ホールド、Undo、クリア、失敗、マップのコマ到着、広告によるライフ回復に対応します。ドラッグ中の仮吸着やスクロールでは鳴らしません。設定の「サウンド」で一括ON/OFFでき、端末に保存します。初期値はONで、最初のユーザー操作後に音声を有効にします。Safari向けにタップ完了時にも音声の初期化・再開を試み、無音バッファで音声出力を準備します。OFFへの切り替え・画面の非表示・フォーカス喪失時は再生中の音を止めます。音声非対応・保存不可でもゲームは継続します。BGMはありません。音量・音色は `js/audio.js` にまとめています。

検証：`node tests/audio.cjs`

通常マップの開始スタミナのプレビューは実際と同じコース生成・ルート探索・紫ホールドの追加消費から計算します。生成状態を一時的に分離して元へ戻し、ライフ・挑戦回数・進行・現在のプレイには影響しません。結果は最大64件を起動中だけキャッシュします。

マップのステージ開始前モーダルでは、所持ハート（初期5個）から使用数を選択できます。1個につきそのプレイの開始スタミナを1追加し、開始に成功した時点で所持数を消費・保存します。閉じる・開始取消・生成失敗では消費しません。リトライ・再開始・次ステージ・マップ復帰後には追加分を持ち越しません。デイリーにはこのアイテム欄を設けません。コース上の回復ハートとライフは従来どおりです。

Canvasは入力・状態変更・画像読込・画面サイズ変更で更新し、カメラ移動・姿勢の収束・短い操作エフェクト中だけ連続描画します。静止中、設定・結果モーダル中は連続描画しません。ゴールのきらめきは独立した小さなCSSレイヤーで動かし、全体の再描画を発生させません。モーダル中は装飾アニメーションも一時停止します。ライフは回復期限、0個時の回復カウントと広告は秒単位、カレンダーは次の午前0時に更新します。非表示時は描画とUIタイマーを停止し、復帰時に現在時刻と照合します。

プレイヤーのマップ・ライフ用アイコンは、保存済みの外見データから透過PNG（96×128px、基準24×32pxの4倍）を生成し、同じ画像を共用します。起動後の初回表示と外見変更の保存時だけ生成し、編集途中や表示更新のたびには再生成しません。編集キャンセルでは元の画像を維持します。保存の正本は従来の色情報で、PNGはメモリ内の派生キャッシュです。画像データには形式・サイズ・生成バージョンを付け、将来のプレイヤー別画像の保存・配信に利用できます。Canvasが利用できない場合は従来のCSSアイコンへ戻ります。

ステージマップには、ランキングと同じ配色のダミープレイヤーを到達ステージ付近へ各ステージ最大5体表示します。本人の現在地マーカー用の場所とステージ番号を避けて配置し、本人を含めアイコンの下端がマップの下側にあるほど手前へ描画します。ダミーの到達先はページ・コースごとに固定し、再表示で入れ替わりません。描画は表示中の20ステージだけで最大100体、追加のコース生成・PNG生成・継続アニメーションはありません。装飾レイヤーはタップやスクロールを妨げません。`node tests/map-players.cjs` で表示上限、重なり順、ページ・コース切り替え、幅変更と移動中の本人の描画順を検証できます。

当日分のデイリーチャレンジをクリアすると、結果画面から広告→アイテム獲得ルーレット→カレンダーの順に進みます。ルーレットはハート＋1・＋5を各2/6（120度）、ハート＋10・ライフ＋1を各1/6（60度）に分割した4区画で、画面タップまたはEnter／Spaceで減速し、止まった報酬を加算・保存して結果をタップして戻ります。ライフは既存の上限5を維持します。過去日のクリアは対象外です。未受取と広告完了の状態を保存し、中断後は次にカレンダーを開いたときに再開します。受取済みの報酬は再配布しません。

`js/rewards.js` の `startRewardSequence({onGrant, onReturn})` は呼び出し元を固定しない独立した取得シーケンスです。`onGrant(reward)`は停止時に1回、`onReturn(reward)`は結果表示後に1回呼ばれます。省略時は元の画面へ戻り、プレイ中に挟んだ場合はプレイ計測時間を中断・再開します。ルーレットだけを更新し、背後のステージCanvasは再描画しません。非表示中は回転・減速を一時停止し、確定結果はタップするまで保持します。

通常マップではSTAGE 4・8・12…のクリア時にも、一度だけアイテム取得ルーレットへ進みます。既存の広告が入る場合は広告の後に表示します。未受取の対象ステージにはゴールと同じキラキラを表示し、受取後は消えます。未受取・広告完了・受取済みを保存し、中断時は次回のマップ表示で再開します。デバッグプレイは対象外です。

デイリーの日付選択は、選択ボタンと開始前情報だけを更新します。開始前情報は日付・難易度・コース長・クリア記録とし、スタミナ欄は表示しません。コース生成・ルート探索・開始スタミナの確定はスタート時だけ行います。

## 0.2.1 表記と操作の統一

## 0.2.2 季節のマップ背景

20ステージごとに背景を春→夏→秋→冬の順で切り替え、冬の次は春へ戻ります。STAGE 1〜20は春、21〜40は夏、41〜60は秋、61〜80は冬、81〜100は春です。前後のページ移動や保存済み進行からの再開でも、そのページの季節を表示します。道・広場・ステージアイコンの配置は全季節で共通です。既存の春背景は維持し、採用済みの夏・秋・冬背景を724×2650のWebPとして追加しています。春のみ既存の彩度補正を維持し、他季節は採用画像の色を使用します。起動時に4枚を読み込み準備し、背景切り替えのためのコース再生成や継続処理は行いません。

## 0.2.3 夏・秋背景の彩度

夏と秋の背景は表示時の彩度を0.7に設定し、従来から30%下げます。画像データや道・広場・小物の形と配置は変更しません。春と冬の表示は維持します。

## 0.2.4 プレイ回数による広告

## 0.2.7 想定ムーブとスタミナ消費の分離

難易度3などで、小さくとがったホールドの追加スタミナ消費を想定ムーブにも加算していた問題を修正しました。想定ムーブとスター評価は検証済みルートの移動回数を使い、開始スタミナとハート配置は従来どおり追加消費も含めて算出します。STAGE47では19ムーブ＋追加消費17を「36ムーブ」としていましたが、想定19ムーブになります。コース・ホールド・探索回数は変更しません。

## 0.2.8 スタミナ予算の固定

基本開始スタミナを全難易度・通常／デイリーで「想定ムーブ＋3」に統一し、小さくとがったホールドの追加消費分による予算の増額を廃止します。STAGE47は想定19ムーブ・基本スタミナ22になります。選択した回復アイテムの加算とコース内ハート、ホールドの追加消費は維持します。難易度3の既存検証ルートは追加消費によって途中でスタミナが尽きる場合があります。

## 0.2.9 実消費コストによる経路探索

通常移動1＋新たにつかんだ消費ホールド1個あたり1を、実際の操作・探索・短縮で共通のコストとして使用します。1個つかむ移動は2、2個なら3で、追加の重みは掛けません。消費ホールドを配置した最終レイアウトでコスト順の探索を行い、短縮も移動回数より総消費を優先し、総消費が同じ場合はムーブ数を優先します。自動吸着の距離ルールは変更しません。

難易度3は通常経路を確保できる追加候補を間引き時に残し、検証済み通常経路以外から30〜50％を消費ホールドへ変換します。これにより無条件で経路上のホールドを変換して予算不足にする処理を解消します。最終候補は持ち込みアイテムなし、想定ムーブ＋3、コース内ハートの実際の接触判定で完走を検証し、未検証の経路は採用しません。追加探索は最大1800候補・各コスト層2状態、短縮は各回最大900遷移・2パスに制限し、上限到達時は検証済み経路を維持します。厳密な全経路最小値の保証ではありません。テスト専用のスタミナ増額は廃止しました。

STAGE47は想定18ムーブ・基本スタミナ21の検証経路で、追加スタミナなしの実入力クリアを確認しました。

## 0.2.10 コースの性格・固定ハート・実予算検証

全モードで、基本型／選択型／消費ホールド通過型／ハート回復型／複合型の狙いを難易度別の重みから先に選びます。初期配置と仮経路の成立を確認した後、ハート位置と消費ホールドを含むコースを固定し、実消費コストで再探索・短縮します。検証用コースは初期配置のみ別方式で、以降の処理は共通です。

ハート取得済みビット、総消費、必要な開始予算を探索状態に含め、取得前のスタミナ切れを除外します。追加消費を3以下に制限する旧処理と、基準経路全体を常に消費ホールド化から保護する旧制約を廃止しました。通常移動1＋消費ホールドの新規接触1個につき1の実コストを使い、余分な重みは付けません。開始スタミナは選択経路の移動回数＋3です。探索・短縮の結果でハートを再配置したり、検証用スタミナを足したりしません。

最終経路は持ち込みアイテムなしで、実際の支持・接触とハート取得のタイミングを再生検証します。固定された開始予算で「ハートに接触しない」「消費ホールドを新たにつかまない」比較探索も行います。代替経路が見つからない場合は厳密な必須証明とはせず `required-in-search` と記録し、回復が予算上必要かも別途記録します。狙いと実績が違えば実際の特徴で分類します。分類は内部の検証情報で、プレイヤー向け画面には表示しません。

配置の修正は最大2回、最終探索は1800候補、比較探索は条件ごとに600候補、短縮は各回900遷移・2パスに制限します。失敗や上限到達時は、先に完走検証した安全なコース／経路を保持します。取得状態が変わらない同一姿勢・接触へのループを排除し、予算増額目的の無意味な往復を避けます。再プレイと開始前プレビューは同じシード・配置・予算を再現し、プレビュー中にプレイ中のコースへ変更を持ち込みません。

選択型のハートは、基準経路をそのまま進む場合は避けられる位置を優先し、実際の支持・吸着規則で取得可能なドラッグがあることも確認します。比較検証が例外で失敗した場合は必須と判断せず `unknown` とし、生成・探索の例外時も検証済みの配置へ戻します。

処理時間は `node scripts/benchmark-course-generation.cjs 3 6 40 47 48` でウォームアップ除外の中央値・最大値、配置と比較探索の試行回数を測定できます。この測定は実行環境のJavaScript速度であり、スマートフォンの実測とは区別します。

## 0.2.11 難易度3の消費ホールドを削減

全体の30〜50％を消費ホールドにする割当てを廃止し、ルート上の追加消費目標とルート外の0〜3個を分離します。ルート外は他の消費ホールドと96px以上離し、実際の移動で取得可能な候補だけ採用します。候補の到達確認は最大12個で打ち切り、個数を満たすための再生成は行いません。間引き時に残す追加候補も割合連動から固定6個へ減らします。通常・検証用コース・デイリーで共通です。基本スタミナは想定ムーブ＋3のまま、最終配置とハートの実接触で完走を検証します。

## 0.2.12 配置後の10〜30％変換と探索

難易度3ではホールドとハートを先に固定し、配置済み全ホールド数の10〜30％（個数は切上げ10％〜切捨て30％）を通常ホールドから消費ホールドへ変換します。ルート上の追加消費1〜7を狙う旧制約と、ルート外0〜3個・96px間隔の制約は廃止します。変換後の配置を実消費コストで探索・短縮し、採用経路の移動回数＋3を開始スタミナとして完走を検証します。元の経路が予算不足でも、探索前に棄却しません。

変換対象の選び直しは最大2回。成立しない場合は同じ配置・ハート・10〜30％の範囲で、既知の経路の予算成立を維持する変換へ戻します。この場合も最終配置で探索・検証します。間引き時に下限10％を満たす選択肢を残し、割合を満たすためのホールド追加は行いません。通常・検証用コース・デイリーで共通処理です。難易度0〜2は従来のルールを維持します。

デイリーの狙いを選ぶ前に日付の基準シードへ戻し、生成に内部再試行が必要だった場合も、リトライで同じ配置・ハート・スタミナになるようにします。

## 0.2.13 難易度2の消費型の追加消費目標

難易度2の消費ホールド通過型は、仮ルートの追加消費目標を1〜3から3〜5へ変更します。目標は個数ではなく、新規保持・持ち替え・再保持に掛かる追加スタミナ消費です。最終経路の開始スタミナは想定ムーブ＋3のまま、実消費とハート取得を含めた完走検証を維持します。

## 0.2.14 コース長を生成の最初に抽選

5の倍数をロングにするルールを廃止し、初期パスを作る前にショート／ミドル／ロングを各1/3の重みで選びます。選択は難易度と独立したシード付き乱数を使い、STAGE1の専用ショートコースは維持します。高さ上限は700／1399／2100px。初期パス規模も長さに合わせて0.5／1／1.6倍とし、ショートが長いパスを縦につぶしただけにならないようにします。

通常・検証用コース・デイリーで共通の長さ抽選と生成条件を使います。マップの壁アイコンと開始前表示も同じ抽選結果を参照し、プレビューとリトライで一致します。デイリーでは日付の基準シードで長さを固定し、内部の地形再生成でも選んだ長さを維持します。

## 0.2.15 選択したコース長の上端まで経路を生成

壁の高さはショート700px／ミドル1400px／ロング2100pxに固定し、STAGE1以外はゴールが上端から約100pxになるまで仮経路のホールドを追加します。従来の固定パス規模と倍率を廃止し、経路不足によってゴールが低くなることを防ぎます。ホールド間隔を保ち、最後の追加による目標高度の超過分だけ縦方向に縮めます。手足の到達距離を超える引き伸ばしは行いません。STAGE1の専用経路、各長さ1/3の抽選、デイリーの長さ固定、最終経路の完走検証は維持します。ショートもゴールの表示余白を含めてスクロールできます。

## 0.2.16 リトライ時のアイテム選択

通常ステージ・検証用コースの登頂失敗後は、リトライでステージ画面を残したまま共通の開始前モーダルを開きます。アイテム選択は毎回0個から始め、スタートを押したときだけ経路・スタミナ・タイマーをリセットし、選択した所持アイテムを一度だけ消費します。前回の追加スタミナは持ち越しません。閉じるボタン・モーダル外タップ・Escapeで閉じた場合はマップへ戻り、開始や追加消費は行いません。

ステージ終了時の広告、ライフ0時の回復案内と広告を終えた場合も、まず開始前モーダルを開きます。開始前にライフが0になった場合は、回復後に選択を確認し直します。生成失敗時にはアイテムを消費せず、ライフを重複消費しません。デイリーは従来の専用リトライ処理を維持します。

## 0.2.17 タイトル背景・コース長の比率・同じUIDの引き継ぎ

コース長の抽選重みをショート2／ミドル5／ロング3へ変更し、STAGE1はショート固定を維持します。タイトルはステージの壁画像を使い、最下段から最上部まで300秒で一度だけスクロールします。最上部で停止し、引き継ぎ画面を開いている間も停止します。タイトルへ戻ると最下段から再開します。

左下の「データ引き継ぎ」でJSONファイルをエクスポートし、別端末で内容を確認してインポートできます。進行・記録・デイリーのメダルと報酬・見た目・所持アイテム・ライフ・設定・未送信スコアを含みます。ファイルには認証情報も入るため、所持者は同じUIDで復元できます。アプリが暗号学的乱数で引き継ぎ専用のメール形式IDとパスワードを作り、現在の匿名ユーザーへ `linkWithCredential` で紐づけます。インポートは `signInWithEmailAndPassword` とサーバーが返すUIDの照合を行い、Firebase SDK内部の保存形式やトークンのコピーは使いません。利用者によるメールアドレス入力・メール受信は不要です。

Firebase Consoleの「セキュリティ → Authentication → ログイン方法」で「メール／パスワード」を有効にして保存してください。「メールリンク」は不要です。この設定が無効な場合は、エクスポート画面で設定案内を表示します。Firestoreルールやインデックスの変更は不要です。外部サービスを使った実端末間の確認は、この設定を有効にした後に行います。

認証の切替中はオンライン書き込みを止め、進行中の保存が終わってから復元します。認証・UID照合・削除済みアカウント確認が終わるまではローカルデータを変更しません。保存に失敗した場合は元のローカルデータと認証へ戻します。復元成功後は再読み込みし、移行先にある別ユーザーの認証アカウントは自動削除しません。削除機能では引き継ぎ用認証情報も端末から削除します。

検証: `node tests/transfer.cjs`、`node tests/firebase-client.cjs`、`node tests/title-startup.cjs`、`node tests/course-length.cjs`。

## 表示文言

通常プレイの表示文言213件は `js/text-ja.js` の `GAME_TEXT_JA` に集約しています。デバッグ機能とユーザーデータ削除の保守用文言30件は `js/text-dev-ja.js` の `GAME_DEV_TEXT_JA` に分けています。使われていなかった19件と参照コードを削除し、現在表示する日本語の内容は維持しています。`js/text.js` の `gameText(key, values)` を通して参照し、数値・日付・ユーザー名は `{value0}` などの名前付きプレースホルダーへ渡します。置換は1回だけで、差し込んだ文字列を再解釈しません。HTML/SVGの構造、保存キー、認証情報、ユーザーが入力した名前は文言辞書に含めません。

静的HTMLは `data-i18n`、読み上げ文言等は `data-i18n-aria-label` / `data-i18n-alt` で初期化します。辞書と参照処理はゲーム初期化より先にdeferで読み込むため、初回スクリプト読み込み後に文言を取得する通信はありません。日本語固定の抽出段階であり、言語選択による切り替え・英訳は次の工程です。英語辞書では同じキーとプレースホルダー名を使い、語順を変更できます。

文言変更時は `node tests/text.cjs` と `python tests/text-static.py` を実行してください。前者は辞書と参照の両方向を検査し、参照切れと未使用キーを検出します。後者は整理後の静的文言・読み上げ文言のスナップショットを検証するため、意図して文章を変更する際には期待値も見直します。
