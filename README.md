# ASCENT

フィールドの任意の位置からスワイプし、1つの支持点を固定し、他の3本を動かして登るクライミングパズルです。最新のゲーム仕様は [GAME_SPEC.md](GAME_SPEC.md) を参照してください。

## 実行方法

[index.html](index.html) をブラウザで開きます。インストール、ビルド、開発サーバーは不要です。`js/` と `styles.css` を含むフォルダー構成を保ってください。

ファイルを編集・保存した後、ブラウザを再読み込みすると変更が反映されます。デバッグパスと画面下の密度評価を使って配置を確認できます。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| [index.html](index.html) | 画面のHTMLと、スクリプトの読み込み順 |
| [styles.css](styles.css) | 画面レイアウト、色、ボタン、レスポンシブ表示 |
| [js/config.js](js/config.js) | 胴体サイズ、可動域、ステージ、密度、操作、カメラの調整値 |
| [js/utils.js](js/utils.js) | 座標計算、シード付き乱数、吸着目標の計算 |
| [js/stage.js](js/stage.js) | コース・ホールド生成、密度評価、反復調整 |
| [js/route.js](js/route.js) | 現行操作でルート探索、余分なホールドの削減、クリア手順の再検証 |
| [js/game.js](js/game.js) | ゲーム状態、支点選択、移動制限、吸着、手数、勝敗、UI更新 |
| [js/input.js](js/input.js) | マウス・タッチ・ボタンのイベント登録 |
| [js/renderer.js](js/renderer.js) | 胴体・四肢・ホールド・デバッグパスの描画、カメラ追従 |
| [js/main.js](js/main.js) | 最初のステージと描画ループの開始 |

## 調整の入口

まず [js/config.js](js/config.js) の次の値を変更します。

| 調整したい内容 | 設定 |
| --- | --- |
| 胴体の形とつかめる範囲 | `TORSO` |
| 可動域 | `LIMB_LENGTHS` |
| ステージの高さ上限 | `MAX_HEIGHT` |
| 初期コースの規模・余裕手数 | `STAGE_CONFIG.baseMoves`、`movesPerLevel`、`growthLevels`、`spareMoves` |
| 左右への振れ幅 | `STAGE_CONFIG.horizontalAmplitude` |
| コースの縦方向の進み方 | `STAGE_CONFIG.pitchBase`、`pitchVariation` |
| 追加ホールドの間隔・散らばり方 | `HOLD_SPACING`、`HOLD_CONFIG` |
| 密度評価と空白の許容範囲 | `DENSITY_CONFIG` |
| 支点選択までの入力距離・吸着目標 | `INPUT_CONFIG` |
| カメラの追従 | `CAMERA_CONFIG` |

密度の基準個数はステージ1を生成して測定します。ホールドの配置条件を変更すると、この基準も変化します。ステージ1の想定手数は5手です。可動域・支持点の配置・吸着設定を変更した後に、ルートを確認してください。

生成方法そのものを変える場合は `js/stage.js`、操作ルールは `js/game.js`、プレイヤーやデバッグ表示の見た目は `js/renderer.js` を編集します。

## 読み込みと状態の扱い

`index.html` に記載した順序で、通常のスクリプトを `defer` 付きで読み込みます。`file://` で直接開ける構成です。

設定と共通関数を読み込み、ステージ生成、ゲーム処理、ルート検証、入力、描画を準備してから `main.js` で開始します。ゲーム状態は `game.js` が保持し、入力・描画処理が参照します。

ステージ生成器は `createStageGenerator()` 内に生成用の状態を保持します。生成結果として、ホールド、参考ルート、高さ、初期支持点、密度評価を返すため、生成途中の状態が進行中のゲーム状態へ混ざりません。

## 確認方法

- 開発者コンソールで `reset(2)` のように実行すると、指定ステージを最初から確認できます。
- ドラッグ中に1本だけが支点として固定され、他の3本が重複せず吸着できるか確認します。
- 参考コースに沿って胴体を移動し、両足先が両手先より上に来ないことを確認します。
- 体型は `TORSO`、腕・脚の長さは `LIMB_LENGTHS`、手足を開いた目標位置は `limbs` で調整できます。
- 密度表示の最大個数・基準・調整回数と、局所的な空白を確認します。
- ステージ1の5手クリア、リトライ、手数切れ、最後の1手でのクリアを確認します。
- マウスとタッチ双方で確認します。

## ルート検証

表示する青点線は、現在の支点選択・吸着条件・両手ゴールで検証した胴体の手順です。現在位置から次の番号へ向かう方向にスワイプしてください。スタミナは検証手順＋1手です。探索は候補を絞る方式で、最短手数は保証しません。

配置生成後、検証ルートで未使用のホールドを壁全体から削除します。その後、ルートの連続する2手以内に対応する短い分岐を最大2個ずつ、全体で最大4個戻します。分岐同士が直接つながらないよう離し、検証ルートの吸着先が変わる追加は却下します。これは長い別ルートを抑える配置上の制約で、任意の操作が必ず2手で復帰する保証ではありません。調整後は `node tests/routes.cjs` でステージ1〜20を検証できます。

デバッグパスは初期OFFです。「想定パスを表示」をONにすると検証済みルートを表示できます。
